The GitHub release assets are available at https://github.com/villagesql/villagesql-server/releases.

## What's New

### Extensions

- **Per-session system variables (preview)** — Extensions can declare per-session system variables through the `vsql::session_var` capability, the session-scoped sibling of `vsql::sys_var`. Every connection holds its own value, settable with `SET SESSION`, and the declared default is the global default. `INT` and `STR` variables are supported. A VDF reads the calling session's value through `int_var()`, `get_session_int()` or `get_session_str()`. Like every preview capability, it requires `vsql_allow_preview_extensions=ON`. The server side backports the component session-variable service and its reader service from upstream MySQL. (`699a0bbf286`, #1059; `494c58d1770`, #1057; `9fd09db4f34`, #1115)
- **Enum system variables** — The `vsql::sys_var` capability gains `make_enum()`. The value is one of a fixed, ordered list of names, stored as its zero-based index; the server validates at `SET` time and rejects a name that is not on the list, unlike a free-form string variable. (`26e94477f9f`, #1179)
- **Client information in statement events** — The `vsql::preview::statement_event` capability now reports the client's connection attributes: the client process id (`_pid`), the connector library (`_client_name`) and the application name (`program_name`). Each is `NULL` when the client did not send it. (`89e0e43f38e`, #1178)
- **Persisted extension variables apply at `INSTALL`** — A persisted value for an extension variable with an `on_change` callback was applied before the variable was recorded in the registry, so the update handler found nothing to write. An `INT` silently kept its default. A string variable was left pointing at memory MySQL had already freed, and `UNINSTALL EXTENSION` freed it again: an assert on debug builds, heap corruption on release builds. The typed write is now unconditional, and `on_change` fires for a persisted value applied at `INSTALL`. A `SET` that races an `UNINSTALL EXTENSION` no longer crashes. (`361196a45d1`, #1129)
- **`STRING` results carry their declared character set** — A VDF registered with `.returns(STRING)` declared `utf8mb4_bin` in its metadata but returned a binary-charset string at runtime. The JSON functions decide text versus binary from the runtime charset, so `JSON_OBJECT('ts', UUID_TIMESTAMP(u))` produced `{"ts": "base64:type15:..."}` unless the caller wrapped the value in `CONVERT(... USING utf8mb4)`. The runtime charset now matches the declared one. (`e6c298d8925`, #1054)
- **VEB installs are synced to disk** — `INSTALL EXTENSION` now `fsync()`s the files and directories it writes from a VEB. (`ea958becc70`, #1145)
- **SDK version comes from the server build** — The SDK version is generated from the server build version and no longer carries the codebase name. (`323a6ec9265`, #1096; `f892efbb034`, #1064)
- **SDK documentation** — The useful comments from the v1-style SDK moved to the `vsql` SDK and the v1 comments were removed, so nobody picks up the old API by accident. The C++ SDK comments stop describing the typed API as wrappers. The header comments on intrinsic defaults said a computed default took precedence over a string default and gave the default VDF an `INT` argument. Declaring both is rejected at registration and the VDF takes no arguments, and the comments now say so. (`3d0d1484935`, #901; `a5d49e67f99`, #898; `8682dfe1528`, #1170)

### Custom Types

- **Type parameters are validated** — For the `TYPE`, `TYPE(N)` and `TYPE('k=v,...')` forms, the server now rejects a duplicate parameter name, a nameless parameter and a parameter with no value before the extension's `resolve_params` callback runs. After the callback returns, a rewrite that dropped a parameter is rejected. Adding parameters and changing values stays legal. (`c17123af77d`, #915)
- **`DROP DATABASE` removes stored program parameter metadata** — Dropping a database bypassed the per-routine `DROP` path that cleans up `villagesql.custom_sp_params`. Rows for procedures and functions with custom-type parameters in the dropped database were left behind. They are now deleted with the database. (`738b26db28d`, #1121)

### Information Schema

- **`sys` view column nullability matches upstream** — Four `sys` views that read the VillageSQL overrides of `INFORMATION_SCHEMA.COLUMNS` and `INFORMATION_SCHEMA.STATISTICS` recorded columns as `NOT NULL` where upstream MySQL records them as nullable: `schema_object_overview`, `x$schema_flattened_keys`, `schema_auto_increment_columns` and `schema_redundant_indexes`. Upstream creates its views in strict mode, where a `COLLATE` or `CONCAT` column stays nullable; the overrides are created with `sql_mode = 0`, where it does not. The server now replays the four views' DDL at startup. The `schema_auto_increment_columns` drift dates from the `COLUMNS` override in 0.0.1. (`f595f2e2251`, #1110)

### Custom Indexes (in development)

Custom index DDL is still refused on every build with `Extended Index feature not yet implemented`; only the MTR suites exercise it, under a debug-only switch. The work below landed behind that guard.

- **Metadata and DDL surfaces** — `SHOW CREATE TABLE` renders a custom index as valid DDL, including its type, per-key-part profile and `WITH` parameters. `INFORMATION_SCHEMA.STATISTICS.INDEX_TYPE` and `SHOW INDEX` report the extension's own index type name instead of `BTREE`; `INDEX_TYPE` widens from `varchar(11) utf8mb3_bin` to `varchar(64) utf8mb4_bin`. An externally-stored custom column wider than the key-length limit can now be indexed; the extension is responsible for its own key-size limits. InnoDB implements `col_ref_to_data` and `col_data_to_ref` for extension-managed column storage, with a new `key_pos` parameter; this changes the SDK API, so existing custom index extensions need updating before they compile again. As a consequence of the `INDEX_TYPE` widening, `sys.schema_object_overview.object_type` widens from `varchar(19)` to `varchar(72)`. (`d9eefc101ce`, #1067; `a7929efbb62`, #1076; `93813b3e96e`, #1035; `bd46c3a559e`, #1015; `6f416c97ce8`, #1111)

### Stability

- **Server starts on big-endian platforms** — On a big-endian host the server failed its first start with `Failed to install VillageSQL schema on first run`. The schema id read back from `mysql.schemata` arrives in host byte order and was being converted with a little-endian helper. Verified on `linux/s390x`. (`33efda8d2f9`, #1049)
- **Valgrind memcheck** — A manually dispatched workflow runs the full VillageSQL MTR suite, the unit tests and the bundled extensions under Valgrind memcheck. Extensions are built with `-DVSQL_VALGRIND=ON` under it, so they can compile conditionally. Two indexing defects came out of it: an uninitialized pointer read in `Custom_index::add_profile`, and an uninitialized `dtype_t::extended_storage`. (`cbe719062ed`, #1157; `3cc9f680ca7`, #1160; `c6c8f3faacd`, #1165; `b14c1e68215`, #1169; `76e9c89557e`, #1173)
- **TSAN workflow** — A first ThreadSanitizer workflow, dispatched manually, is checked in for experimentation. Becoming TSAN-clean is tracked in #1183 and not yet done. (`96ca4d8fb1a`, #1185)
- **Test coverage** — Gcov-guided additions to the MTR suites cover the full write-side storage ABI with two column-store columns in one table, the `EXTENSION` MDL wait event, custom-type stored-procedure parameters through a pending upgrade, `FULLTEXT` on tables with custom-type columns, and rollback of extended-storage values. New unit tests cover the deferred extension version update stored in `villagesql.extensions.pending_action`, semver edge cases, and `TypeContext`. An extension downgrade test exercises `ALTER EXTENSION` to an earlier version. A test covers the locking assumptions behind a suspected crash, an `UNINSTALL EXTENSION` racing a `SET GLOBAL` on an extension variable. (`d665614d687`, #984; `54ce39b7620`, #957; `e6f17e8c41f`, #1153; `bb95002a73a`, #1137; `10a099c37bd`, #1123)

### Build & Compatibility

- **Ubuntu 26.04 builds** — The CI runners moved to Ubuntu 26.04, and the newer compiler surfaced new diagnostics. One more libarchive warning is allowlisted. A latent bug is fixed: `TypeParameters::from_raw()` lower-cased an empty parameter name or value, which is undefined behavior. An upstream MySQL bug in the Group Replication plugin's call to `inet_ntop()`, which passed the size of the address struct where the size of the destination buffer belongs, is corrected. A LeakSanitizer suppression covers the Rust coreutils that newer Ubuntu ships. (`cf3499be13c`, #1097; `9057fe31137`, #1107; `9d85e0a5119`, #1108)
- **Docker image streams the bootstrap server's log** — The entrypoint printed the temporary server's log once, when the server reported ready, so anything written after that was lost if the script exited early. The log is now tailed to stderr continuously. (`06ae8da633c`, #1152)
- **Docker dev container runs as non-root** — The development container creates a user with the host's uid, gid, user name and group name. Files written back to the host keep the host user as owner, and MTR tests that start `mysqld` themselves no longer fail for lack of `--user=root`. The container also adds a data directory volume, drops the hardcoded resource limits, and grants the user password-less `sudo`. Rebuild the image with `docker/dev/build.sh` on the machine that will run it. (`85f12e9eb14`, #1126)
- **Docker Hub manifests for multiple codebases** — The publish workflows push and tag multi-platform manifests per codebase, so each codebase has its own `latest` (`mysql-8.4_latest`, `mysql-9.7_latest`, `percona-8.4_latest`) and Docker Hub selects the right platform image. Release images are tagged per codebase, for example `mysql-8.4_0.0.7`. The `linux/amd64` image builds moved from GitHub's `ubuntu-latest` to the VillageSQL self-hosted runner pool. (`6f1c4988e37`, #1065; `4dbfcca7c5a`, #1174)
- **Release automation** — The acceptance test for a codebase release branch and the generation of release artifacts run as dispatched workflows. Scripts create the draft GitHub release from the tag and the release notes, and finalize the release notes header. (`2b985c04f13`, #1083; `2b99129bcfc`, #1125; `5e8ab844da8`, #1082; `b4344ce7dda`, #1086; `3b47edc9de8`, #1091)
- **Nightly and full test suite CI** — The sanitizer and extension-compat workflows are driven by the nightly dispatch rather than an unparameterized trigger. The Full Test Suite can choose its runner and gains a nightly macOS run. Test reporting includes retry details and preserves results when MTR reruns unstable tests to success. The slow `max_parts` tests and three other long-running tests get testcase timeouts sized to GitHub runner speed. `lock_order.cycle`, which needs a server built with `-DWITH_LOCK_ORDER=ON`, is disabled. (`39d5d8b8955`, #1071; `a7790b71ef2`, #1072; `6442c74867e`, #1038; `6d147a1b021`, #1114; `2deed4a37f8`, #1146; `2c7bb6fa3a6`, #1130; `2a1a1344475`, #1134; `4d7152888a8`, #1163; `7f8af9db1c8`, #1164; `2eb58eefbb6`, #1167; `41181a73177`, #1166)
- **Pull request checks** — A pull request may carry more than one `area/` or `kind/` label, and the label checker action is bumped past an expired Debian base image. The PR title check allows 63 characters, up from 41, so a squash-merged title stays under GitHub's 72-character limit. The `villint` tests no longer depend on a global git config. (`84c2534fa70`, #1085; `175d3dc9f23`, #1124; `f436c0f953b`, #1080; `aba58cfba3f`, #1176)
- **README and policy** — The README test steps pass `--nounit-tests`, since the upstream unit tests have a couple of known failures, and its roadmap section points at the published roadmap instead of carrying its own list. The bundled-extension build scripts document their inputs. The AI policy in the contributing guide now covers issues as well as pull requests and states that AI code review assistants such as Copilot are not allowed. (`030bccd2aae`, #1141; `99ed4310e91`, #1147; `6dc6ca1c6c9`, #1061; `aa68a9c2a55`, #1056)

## Known Issues

- **`--initialize` with `--default_table_encryption=ON` aborts** — Upstream MySQL 8.4.11 (the fix for Bug#39114059) assumes the `mysql` tablespace is unencrypted during initialization. With `--default_table_encryption=ON` that assumption is false, so `mysqld --initialize` aborts with `ERROR 3825 Request to create 'unencrypted' table while using an 'encrypted' tablespace` and leaves the new data directory unusable. A fix is in progress on `dbentley/fix-initialize-encryption`.
