## What's New

### Extensions

- **Per-session system variables (preview)** — Extensions can declare per-session system variables through the `vsql::session_var` capability, the session-scoped sibling of `vsql::sys_var`. Every connection holds its own value, settable with `SET SESSION`, with the declared default as the global default. `INT` and `STR` variables are supported, and a VDF reads the calling session's value through `int_var()`, `get_session_int()` or `get_session_str()`. The server side backports the component session-variable service and its companion reader service from MySQL 9.7, with the copied files kept byte-for-byte identical to upstream so the eventual rebase merges cleanly. (`699a0bbf286`, #1059; `494c58d1770`, #1057; `9fd09db4f34`, #1115)
- **Enum system variables** — The `vsql::sys_var` capability gains `make_enum()`. The value is one of a fixed, ordered list of names, stored as its zero-based index; the server validates at `SET` time and rejects a name that is not on the list, unlike a free-form string variable. (`26e94477f9f`, #1179)
- **Client information in statement events** — The statement-event capability now reports the client's connection attributes: the client process id (`_pid`), the connector library (`_client_name`) and the application name (`program_name`). Each is `NULL` when the client did not send it. (`89e0e43f38e`, #1178)
- **Persisted extension variable values were dropped, and a string variable could be freed twice** — When an extension variable with an `on_change` callback had a persisted value, the value was applied before the variable was recorded in the registry, so the update handler found nothing and did no write. An `INT` silently kept its default. A string variable was worse: MySQL freed the old buffer as soon as the handler returned, the storage pointed at freed memory, and `UNINSTALL EXTENSION` freed it again — an assert on debug builds, heap corruption on release builds. The typed write is now unconditional, and `on_change` fires for a persisted value applied at `INSTALL`. (`361196a45d1`, #1129)
- **`STRING` results carry their declared character set** — A VDF registered with `.returns(STRING)` declared `utf8mb4_bin` in its metadata but returned a binary-charset string at runtime. The JSON functions decide text versus binary from the runtime charset, so `JSON_OBJECT('ts', UUID_TIMESTAMP(u))` produced `{"ts": "base64:type15:..."}` unless the caller wrapped the value in `CONVERT(... USING utf8mb4)`. The runtime charset now matches the declared one. (`e6c298d8925`, #1054)
- **VEB installs are synced to disk** — `INSTALL EXTENSION` now `fsync()`s the files and directories it writes from a VEB. (`ea958becc70`, #1145)
- **SDK version comes from the server build** — The SDK version is generated from the server build version, with a test that checks it, and no longer carries the codebase name. (`323a6ec9265`, #1096; `f892efbb034`, #1064)
- **SDK documentation** — The useful comments from the v1-style SDK moved to the `vsql` SDK and the v1 comments were removed, so nobody picks up the old API by accident. The word "wrapper" is gone from the C++ SDK docs. The header comments on intrinsic defaults said a computed default took precedence over a string default; in fact declaring both is rejected at registration, and the comments now say so. (`3d0d1484935`, #901; `a5d49e67f99`, #898; `8682dfe1528`, #1170)

### Custom Types

- **Type parameters are validated** — For the `TYPE`, `TYPE(N)` and `TYPE('k=v,...')` forms, the server now rejects a duplicate parameter name, a nameless parameter and a parameter with no value before the extension's `resolve_params` callback runs, and rejects a rewrite that dropped a parameter after it returns. Adding parameters and changing values stays legal. (`c17123af77d`, #915)
- **`DROP DATABASE` removes stored program parameter metadata** — Dropping a database bypassed the per-routine `DROP` path that cleans up `villagesql.custom_sp_params`, so rows for procedures and functions with custom-type parameters in the dropped database were left behind. They are now deleted with the database. (`738b26db28d`, #1121)

### Information Schema

- **Column nullability matches upstream** — VillageSQL's overrides of `INFORMATION_SCHEMA.COLUMNS` and `INFORMATION_SCHEMA.STATISTICS` reported `IS_NULLABLE = NO` on columns where upstream MySQL reports `YES`. The upstream views are created in strict mode, where a `COLLATE` clause leaves the column nullable; the overrides were created with `sql_mode = 0`, where it does not. The four affected views now replay their DDL at startup, and the same drift in `sys.schema_auto_increment_columns`, present since the `COLUMNS` override in 0.0.1, is corrected. (`f595f2e2251`, #1110)

### Custom Indexes (in development)

Custom index DDL is still refused on every build with `Extended Index feature not yet implemented`; only the MTR suites exercise it, under a debug-only switch. The work below landed behind that guard.

- **Metadata and DDL surfaces** — `SHOW CREATE TABLE` renders a custom index as valid DDL, including its type, per-key-part profile and `WITH` parameters. `INFORMATION_SCHEMA.STATISTICS.INDEX_TYPE` and `SHOW INDEX` report the extension's own index type name instead of `BTREE`; `INDEX_TYPE` widens from `varchar(11) utf8mb3_bin` to `varchar(64) utf8mb4_bin`. An externally-stored custom column wider than the key-length limit can now be indexed, since the index keys on the column's inline reference rather than its value. The SDK adds `col_ref_to_data` and `col_data_to_ref` for extension-managed column storage; this changes the SDK API, so existing custom index extensions need updating before they compile again. (`d9eefc101ce`, #1067; `a7929efbb62`, #1076; `93813b3e96e`, #1035; `bd46c3a559e`, #1015; `6f416c97ce8`, #1111)

### Stability

- **Server starts on big-endian platforms** — On a big-endian host the server failed its first start with `Failed to install VillageSQL schema on first run`. The schema id read back from `mysql.schemata` arrives in host byte order and was being converted with a little-endian helper. Verified on `linux/s390x`. (`33efda8d2f9`, #1049)
- **Valgrind memcheck runs in CI** — The MTR suites, the unit tests and the bundled extensions now run under Valgrind memcheck, with a Valgrind signal plumbed through to extensions so they can compile conditionally. Two indexing defects came out of it: an uninitialized pointer read in `Custom_index::add_profile`, and an uninitialized `dtype_t::extended_storage`. (`cbe719062ed`, #1157; `3cc9f680ca7`, #1160; `c6c8f3faacd`, #1165; `b14c1e68215`, #1169; `76e9c89557e`, #1173; `9d85e0a5119`, #1108)
- **TSAN workflow** — A first ThreadSanitizer workflow is checked in for experimentation. Becoming TSAN-clean is tracked separately and not yet done. (`96ca4d8fb1a`, #1185)
- **Test coverage** — Gcov-guided additions to the MTR suites cover the full write-side storage ABI with two column-store columns in one table, the `EXTENSION` MDL wait event, custom-type stored-procedure parameters through a pending upgrade, `FULLTEXT` on tables with custom-type columns, and rollback of extended-storage values. New unit tests cover the deferred extension version update stored in `villagesql.extensions.pending_action`, semver edge cases, and `TypeContext`. An extension downgrade test exercises `ALTER EXTENSION` to an earlier version, and a test covers the locking assumptions behind a suspected crash. (`d665614d687`, #984; `54ce39b7620`, #957; `e6f17e8c41f`, #1153; `bb95002a73a`, #1137; `10a099c37bd`, #1123)

### Build & Compatibility

- **Ubuntu 26.04 builds** — The GitHub runner image moved to Ubuntu 26.04 and its newer compiler surfaced new diagnostics: more libarchive warnings are allowlisted, a latent bug is fixed, and an upstream MySQL bug in a call to `inet_ntop()`, which passed the size of the address struct where the size of the destination buffer belongs, is corrected. (`cf3499be13c`, #1097; `9057fe31137`, #1107)
- **Docker image streams the bootstrap server's log** — The entrypoint printed the temporary server's output in one batch after shutting it down, so an early exit lost it. The output is now tailed to stderr continuously. (`06ae8da633c`, #1152)
- **Docker dev container runs as non-root** — The development container creates a user with the host's uid, gid, user name and group name, so files written back to the host keep sane ownership, and MTR tests that start `mysqld` themselves no longer fail for lack of `--user=root`. It also adds a data directory volume, drops the hardcoded resource limits, and grants the user password-less `sudo`. (`85f12e9eb14`, #1126)
- **Docker Hub manifests for multiple codebases** — The publish workflows push and tag multi-platform manifests per codebase, so `latest` has a sensible meaning for each and Docker Hub selects the right platform image. The `linux/amd64` image builds moved from GitHub's `ubuntu-latest` to the VillageSQL self-hosted runner pool. (`6f1c4988e37`, #1065; `4dbfcca7c5a`, #1174)
- **Release automation** — The acceptance test for a codebase release branch, the generation of release artifacts, the creation of the draft GitHub release from the tag and the release notes, and the final edit of the release notes are now workflows and scripts rather than hand steps. (`2b985c04f13`, #1083; `2b99129bcfc`, #1125; `5e8ab844da8`, #1082; `b4344ce7dda`, #1086; `3b47edc9de8`, #1091)
- **Nightly and full test suite CI** — The sanitizer and extension-compat workflows are driven by the nightly dispatch rather than an unparameterized trigger. The Full Test Suite can choose its runner and gains a nightly macOS run. Test reporting includes retry details and preserves results when MTR reruns unstable tests to success. The slow `max_parts` tests and three other long-running tests get testcase timeouts sized to GitHub runner speed, and `lock_order.cycle`, which needs compiler options not in normal use, is disabled. (`39d5d8b8955`, #1071; `a7790b71ef2`, #1072; `6442c74867e`, #1038; `6d147a1b021`, #1114; `2deed4a37f8`, #1146; `2c7bb6fa3a6`, #1130; `2a1a1344475`, #1134; `4d7152888a8`, #1163; `7f8af9db1c8`, #1164; `2eb58eefbb6`, #1167; `41181a73177`, #1166; `b9627d8297e`, #1161; `87a1b023c91`, #1150)
- **Pull request checks and `villint`** — A pull request may carry more than one `kind/` label, and the label checker action is bumped past an expired Debian base image. `villint` allows a 72-character first line on commit messages, up from 50, and its tests no longer depend on a global git config. (`84c2534fa70`, #1085; `175d3dc9f23`, #1124; `f436c0f953b`, #1080; `aba58cfba3f`, #1176)
- **README and policy** — The README test steps pass `--nounit-tests`, since the upstream unit tests have a couple of known failures; the bundled extension testing steps are completed; the roadmap section points at the published roadmap instead of carrying its own list. The AI policy now covers issues as well as pull requests and states that AI code review tools such as Copilot are not allowed. (`030bccd2aae`, #1141; `99ed4310e91`, #1147; `6dc6ca1c6c9`, #1061; `aa68a9c2a55`, #1056)
